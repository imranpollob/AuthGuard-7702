# Collection Report

Generated by `dataset_pipeline/scripts/01_collect_authorizations.py` +
`02_recover_signers_and_bytecode.py`, config `configs/dataset_pipeline.json`.

Two runs exist: `v1` (2,001-block pilot, used to validate the pipeline end to end before
scaling up) and `v2` (the primary run this report describes). Both are preserved on disk;
downstream stages (families, evidence, LLM review, human review) operate on `v2`.

## Scope

- Chain: Ethereum mainnet only (config supports more; only `ethereum` is enabled).
- Block range: **25,595,577 – 25,695,577** (100,001 requested blocks; the run resumed once
  after a transient RPC parsing failure — see "Incidents" below — so it actually scanned
  **100,444** blocks by the time it finished, since `latest` had advanced by the time the resumed
  run re-resolved its end block).
- RPC: `https://eth.drpc.org` (primary, with `ethereum-rpc.publicnode.com` as failover), no API
  key. No filtering by suspicion, labels, or predictions was applied — every type-0x4
  transaction's authorization-list entries in range were recorded.

## Volumes

| Metric | Count |
|---|---:|
| Blocks scanned | 100,444 |
| Type-0x4 transactions | 374,878 |
| Authorization-list entries | 1,335,391 |
| Entries with a successfully recovered signer | 1,335,384 (99.9995%) |
| Entries where recovered signer ≠ `tx.from` | 1,309,586 (98.07%) |
| Distinct nonzero delegate addresses | 760 |
| Screenable (bytecode retrieved) | 752 |
| NOTSCREENABLE (empty code / fetch failure) | 8 |

7 of 1,335,391 entries failed signer recovery (malformed/out-of-range signature components —
kept in the enriched CSV with `recovered_authority=NaN` and a `recovery_error`, not dropped).
The 98.07% recovered-signer ≠ tx.from rate at full scale confirms the pilot's finding: the
overwhelming majority of observed EIP-7702 authorizations are relayed by a bundler/sponsor
address distinct from the authorizing EOA, so using `tx.from` as a stand-in for the signer would
have been wrong for essentially the whole population.

## Incidents

The first collection attempt crashed after 39,737 blocks with a `json.JSONDecodeError` on a
truncated HTTP response from the RPC endpoint — a transient-network failure mode that
`revision_v3/src/temporal/rpc_client.py`'s own retry loop does not catch (it only retries
`URLError`/`HTTPError`/`TimeoutError`/`RpcError`, not a malformed-but-200-status body). Since
that module is frozen reference material and is not modified by this workflow, the fix was added
in `dataset_pipeline/lib/collector.py`: block-level retry with backoff on `(RpcError, ValueError)`
before giving up and checkpointing. No data was lost — checkpointing already covered every block
before the failure — and the run resumed cleanly from block 25,634,871.

Separately, `coincurve` (the fast C secp256k1 backend `eth_keys` prefers when available) was not
installed in this environment; `eth_keys` was silently falling back to its pure-Python backend,
which benchmarked at ~7.3 ms/recovery (≈2.7 hours projected for 1.34M rows). Installing
`coincurve` dropped this to ~0.14 ms/recovery (≈3 minutes actual).

## Outputs

- `data/collected_delegates/v2_ethereum_authorizations_raw.csv` — raw per-authorization rows.
- `data/collected_delegates/v2_ethereum_authorizations_enriched.csv` — + recovered signer +
  delegate-level first-observed/frequency/bytecode-status fields.
- `data/collected_delegates/v2_ethereum_population.csv` — **the complete collected population**:
  one row per distinct nonzero delegate address, saved before any sampling or labeling.
- `data/collected_delegates/v2_ethereum_population_summary.json`.
- Checkpoints under `data/collected_delegates/checkpoints/` make widening the range resumable.

## Known limitations

- Single chain, single ~100k-block (~2-week) window — not a comprehensive census of EIP-7702
  usage; treat as a substantial but bounded sample. Widening the range is a config change.
- Bytecode was fetched at each delegate's *first-observed* block via a historical `eth_getCode`
  call; later code changes (e.g. if the contract is itself upgraded) are not reflected.
